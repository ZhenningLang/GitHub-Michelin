# concurrent-editing

> 分类节点。并行 agent（或人）写同一个仓库、分支在 `git merge` 处相撞——语义合并驱动与合并分析，让互不相干的改动不再停下来等人。
> ← 返回 [agent-tooling](../INDEX.zh.md) · 根：[分类路由](../../../INDEX.zh.md) · English: [INDEX.md](INDEX.md)

## 本分类下的项目

| 项目 | 何时用 | 健康度 | 页面 |
| --- | --- | --- | --- |
| **LayerFS** | agent 要分叉含依赖的完整工作目录，并在不复制底层的情况下保存检查点；存储不承诺崩溃耐久，合并需复核。 | B（6/6） | [→](layerfs.zh.md) |
| **weave** | 并行 agent 或分支总在同一文件里互不相干的改动上卡住合并、想让 git 比函数和键而不是比行时用它——但它约 8 个月大、pre-1.0、单一核心作者，引擎判定仍在版本间变动。 | B（6/6） | [→](weave.zh.md) |

## 对比矩阵

| 选项 | 是否收录 | 健康度 | 一句话取舍 |
| --- | --- | --- | --- |
| [LayerFS](layerfs.zh.md) | 已收录 | B（6/6） | 共享完整目录内容与私有写视图，不是 Git 合并驱动，也不是具备崩溃耐久性的主存储。 |
| [weave](weave.zh.md) | ✅ | B（6/6） | 跑在现有 git 底下的实体级合并驱动：互不相干的改动不再冲突，代价是把合并结果托付给一台 0.x 的语义引擎。 |
| 原版 git 行级合并加 rerere | 非仓库 | — | 零安装、可审计的基线，但每对同文件内的独立改动都要人停下来解决。 |

## 什么该放这里

坐在版本控制底下、修「并发写作者相撞时会发生什么」的工具：语义合并驱动、合并分析与解释、活写协调。不是人看的那块评审屏（见 `supervision-surfaces`），不是 agent 运行其上的任务/计划状态（见 `work-state`），也不是 LLM 自动产出的评审意见（见 `ai-code-review`）。
