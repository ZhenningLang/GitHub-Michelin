# frameworks

## Sub-categories

| Category | Use when | Route |
|---|---|---|
| **view-frameworks** | Component / view-layer frameworks — the runtime that renders components and manages reactivity in the browser. | [→](view-frameworks/INDEX.md) |
| **app-frameworks** | Full-stack application meta-frameworks and routers — routing, data loading, SSR and server code on top of a view framework. | [→](app-frameworks/INDEX.md) |
| **site-frameworks** | Content- and documentation-site frameworks — the deliverable is a mostly static site built from Markdown/MDX. | [→](site-frameworks/INDEX.md) |

## What belongs here

Front-end frameworks and meta-frameworks for building web applications, split by what you are choosing: the view layer (`view-frameworks`), the application framework or router on top of it (`app-frameworks`), or a framework whose deliverable is a content or docs site (`site-frameworks`). Not component libraries or design systems (see `web-ui/component-libraries`), not browser automation (see `web-automation`), and not typesetting or document compilers that emit PDF rather than a running site (see `typesetting`).
