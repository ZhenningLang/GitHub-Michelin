net-merge：用上闲置链路，但不把一条连接变快

你在电脑上同时接 Wi-Fi 和手机移动数据，游戏更新或多文件下载却只使用其中一条。net-merge 在本机接住 TCP／UDP，把不同新连接交给不同网卡。它不需要远端汇聚服务器，代价是每条连接固定一条路径，没有统一出口 IP，也不迁移已经建立的会话。

什么时候值得考虑

应用会开多条独立连接，且两条链路确实有独立上游时，它能成为工作站多出口工具的候选。若 Wi-Fi 和网线最后都挤在同一条已饱和宽带上，多一张网卡不能消除共同瓶颈。 若目标是一条 TCP 下载或复用连接超过单链路速度，应研究带远端汇聚的多路径方案，而不是直接相加网络标称带宽。若目标是整个局域网的出口策略，应选路由器层方案；若目标是按域名或应用选择代理，应看规则代理工具。

源码改变了哪些 README 直觉

  • 分配对象是套接字，不是每个请求。 TCP 建连前绑定源地址和网卡；UDP 会话也固定出口。UDP 选完后立即释放调度器的活跃负载槽，不能把这个指标当持续 UDP 会话数。
  • 探测成功只说明 TCP 可达。 探测按接口与地址族绑定到公共 IP 的 443 端口，不验证 TLS、HTTP、DNS、UDP 或门户认证。调度器会从已通退到未知，再退到失败层；不能承诺失败链路绝不接收新流。
  • 撤路由不等于恢复会话。 平台清理会尝试恢复状态，但 Windows 的部分共享／转发设置可能等后续启动或清理才恢复，macOS 专属默认路由也可能残留。安装器还涉及提权、软件源和免密控制规则，不能当普通无权限托盘程序。

流量权重来自已经中转的收发字节，整张网卡的系统字节是另一套统计。前者不是主动带宽测试，后者也不能证明流量经过本工具。IPv6 的默认策略与捕获失败还可能分别导致拒绝或绕行，不能把它当 VPN 断网保护。 本轮固定版本为 fe343c69。主会话独立读过探测、TCP／UDP 字节与负载槽和 macOS 安装权限，没有安装或改网。

选择结论： 适合有多连接负载、能承担系统网络改动的试验性工作站。十天仓龄和上游自测速度不足以支持无人值守网关或“崩溃永不掉网”的保证。项目原作 MIT 不覆盖 Windows Wintun DLL 的独立预编译分发条件。

CCBaga：值得读恢复设计，不宜当日常账号的唯一退路
