## net-merge：用上闲置链路，但不把一条连接变快

你在电脑上同时接 Wi-Fi 和手机移动数据，游戏更新或多文件下载却只使用其中一条。net-merge 在本机接住 TCP／UDP，把不同新连接交给不同网卡。它不需要远端汇聚服务器，代价是每条连接固定一条路径，没有统一出口 IP，也不迁移已经建立的会话。

### 什么时候值得考虑

应用会开多条独立连接，且两条链路确实有独立上游时，它能成为工作站多出口工具的候选。若 Wi-Fi 和网线最后都挤在同一条已饱和宽带上，多一张网卡不能消除共同瓶颈。
若目标是一条 TCP 下载或复用连接超过单链路速度，应研究带远端汇聚的多路径方案，而不是直接相加网络标称带宽。若目标是整个局域网的出口策略，应选路由器层方案；若目标是按域名或应用选择代理，应看规则代理工具。

### 源码改变了哪些 README 直觉

- **分配对象是套接字，不是每个请求。** TCP 建连前绑定源地址和网卡；UDP 会话也固定出口。UDP 选完后立即释放调度器的活跃负载槽，不能把这个指标当持续 UDP 会话数。
- **探测成功只说明 TCP 可达。** 探测按接口与地址族绑定到公共 IP 的 443 端口，不验证 TLS、HTTP、DNS、UDP 或门户认证。调度器会从已通退到未知，再退到失败层；不能承诺失败链路绝不接收新流。
- **撤路由不等于恢复会话。** 平台清理会尝试恢复状态，但 Windows 的部分共享／转发设置可能等后续启动或清理才恢复，macOS 专属默认路由也可能残留。安装器还涉及提权、软件源和免密控制规则，不能当普通无权限托盘程序。

流量权重来自已经中转的收发字节，整张网卡的系统字节是另一套统计。前者不是主动带宽测试，后者也不能证明流量经过本工具。IPv6 的默认策略与捕获失败还可能分别导致拒绝或绕行，不能把它当 VPN 断网保护。
本轮固定版本为 [`fe343c69`](https://github.com/rohit267/net-merge/commit/fe343c69b2020bed415e8ed669cee5a7f34d8918)。主会话独立读过[探测](https://github.com/rohit267/net-merge/blob/fe343c69b2020bed415e8ed669cee5a7f34d8918/internal/engine/probe.go)、[TCP／UDP 字节与负载槽](https://github.com/rohit267/net-merge/blob/fe343c69b2020bed415e8ed669cee5a7f34d8918/internal/engine/flowconn.go)和 [macOS 安装权限](https://github.com/rohit267/net-merge/blob/fe343c69b2020bed415e8ed669cee5a7f34d8918/internal/platform/install_darwin.go)，没有安装或改网。

**选择结论：** 适合有多连接负载、能承担系统网络改动的试验性工作站。十天仓龄和上游自测速度不足以支持无人值守网关或“崩溃永不掉网”的保证。项目原作 MIT 不覆盖 Windows Wintun DLL 的独立预编译分发条件。

## CCBaga：值得读恢复设计，不宜当日常账号的唯一退路

CCBaga 处理的是默认 Claude Code／Desktop 的本地登录与文件状态，另可关联独立浏览器资料。它和只改供应商地址的配置切换器不同：会读取并替换选定状态，关闭识别到的客户端，涉及真实凭据和不可逆清理。

### 为什么这次收录，许可却仍未解决

主会话当日再次查询默认分支，仍为 `bdfb90ceadfc5fae6772ffff597bddecb0b73cc3`。
重新读取的 [NOTICE](https://github.com/liseami/CCBaga/blob/bdfb90ceadfc5fae6772ffff597bddecb0b73cc3/NOTICE.md#vendored-interface)仍要求确认 `vendor/cromma-ui` 及其 Pika 子集的再分发条款，补齐必要声明；根 MIT 仅覆盖项目原作代码。
用户知悉该事实后明确选择“带明确警告收录”。这次继续的依据是[维护者裁决](../ccbaga-decision.md)，不是上游补证，也不是重复执行自动解除门槛。它只改变信息索引状态，不代表批准安装、复制 UI、再分发或违反服务条款。

其余四项旧 proposed 没有获得放行。旧提议记录保留历史理由，当前台账的 CCBaga 行另记本次已提交页和裁决，并明确本任务没有关闭任何标签。

### 这次新核的决定性问题

[问题 #49](https://github.com/liseami/CCBaga/issues/49)报告正常生成路径导致身份保存／恢复失败。[修复 #50](https://github.com/liseami/CCBaga/pull/50)在本次查询时仍 open、未合并，基点就是已读版本。
静态读取可见恢复白名单依赖当前路径定义；这和上游失败报告相符，但本轮没有用真实账号复现。不能把“代码有恢复日志”或“修复 PR 已提出”写成日常往返已经可靠。

### 三条不能混淆的边界

- **加密不等于隔离同用户程序。** 每份归档使用认证加密，主密钥仍存在本地，依赖文件权限；解包还会产生受限权限的明文暂存。浏览器资料不在这份加密归档里。
- **有快照不等于每个按钮都能撤销。** 普通切换先验收、留恢复记录并尝试回滚；直接身份删除、残留清理与浏览器全清理是另一条路径，不新增备份、不经废纸篓，中途失败可能已删掉部分内容。
- **环境测量不等于匿名或登录被接受。** 绿色结果比较有限的地区、语言、时区和设备等观测，不授予服务权限，也不证明 DNS／WebRTC 无泄漏、账号不会被关联或浏览器引擎安全。

可选网络部署技能还属于独立安装与授权范围，不是本地账号切换顺带获得的权限。本轮没有接触 SSH 凭据、运行清理或修改远端服务器。
**选择结论：** 目前只建议研究源码或使用可丢弃样本评估；日常账号应保留官方登录路径和独立备份。根许可、机器雷达及本索引均不能填补第三方 UI 权利和实际恢复验收。

## Astro：已有内容站框架条目，本轮不伪造一次刷新

Astro 页核验于 **2026-09-20**，至本轮 UTC 日期为三十二天，未超默认九十天门槛。主会话确认仓库仍公开，并读取既有双语页；没有访问今日上游源码、重新计算健康度、修改原日期或迁移页面结构。

以下用途与限制来自旧页，不是今天重核的版本承诺：当博客、文档、产品或营销站以内容为主，只需少量交互时，Astro 的 HTML 优先与局部交互组件有价值。静态构建省去常驻应用服务；按需渲染则增加托管适配器和服务端运维。
若需求是现成的版本化文档预设，旧页偏向 Docusaurus；若必须共用既有 Next.js 应用运行时，旧页偏向 Next.js／Nextra。它不是生成 PDF、印刷文档或给个人 agent 增加常驻能力的工具。

旧页版本、Node 下限和评分都保留其原时间边界。旧健康正文与 frontmatter 的采用包、响应样本口径存在差异，本轮没有校正；许可轴的问号也没有被擅自改成法律结论。没有把其他项目的依赖故障扩写成 Astro 的普遍已证实缺陷。
**选择结论：** 已有索引入口足够覆盖本次追加请求；采用新版本前再核实该版本要求，不把 fresh 等同于刚重新读过上游。

## 这些项目是否值得吸收到个人 harness

本轮没有足够证据支持 medium／high 的直接接入建议。三者都不是当前必须新增的全局组件，也没有收益实测。
net-merge 属独立高权限网络工具，不自动进入网络初始化；CCBaga 的先验收、持久恢复记录和不可逆删除提示可作设计参考，但不能照搬仍有缺陷的实现；Astro 只在另有内容站需求时才是技术候选。
这里只记录思想，不安装、不修改 dotfiles，也不开实验。把连通性探测当业务验收、把归档成功当恢复保证，都是本轮值得带走的反例。
