# 自进化框架：该吸收什么，不该接管什么

**建议保留现有 harness，优先补行为验收。不要整套迁入自进化框架。**

这份建议来自固定提交的源码对照，不是效果实测。未安装外部框架，未运行上游模型实验，也未修改现有 harness。[当日批次结果](batch.html)（[源稿](batch.md)）保留首轮计数；[2026-10-19 最新汇总](../../tabs-2026-10-19/report/summary.md) 补充 Harness² 研究与公开发布进展。

## 先看结论

现有系统已经能聚合重复摩擦、暂存修改、逐条裁决，再通过独立分支发布。它并不缺另一套“反思后写规则”的入口。主会话复核了落地控制流：默认验证命令只运行技能结构校验，未强制要求候选在真实任务中优于旧版。

**[推断：依据是现有落地控制流与六条上游机制，未做个人任务集实验]** 最值得吸收的是三件事：冻结实验输入、让程序根据原始结果算分、对最终实际发布版本重新验收。模型提出修改，但不能自行定义成功并批准生效。

完整依据：[现有能力与缺口](../harness-baseline.md)、[上游源码证据](../evolution-evidence.md)。

## “自进化”不是同一种能力

| 能力 | 实际改变什么 | 本批代表 | 不能据此推导 |
|---|---|---|---|
| 记忆维护 | 笔记、标签、事实、经验 | Atomic、Hy-Memory | 全局工作流已经改好 |
| 规则提案 | 从失败轨迹生成指令 | Headroom learn | 写入后成功率更高 |
| 基准选优 | 对提示、技能或工具候选打分 | Penguin、Jiuwen RSI | 分数上涨会迁移到未见任务 |
| 事实治理 | 区分待证主张和已晋升事实 | FounderOS 的独立事实子系统 | 置信度等于独立验证 |

这里没有发现个人环境中在线训练模型权重的证据。Hy-Memory 上游称已发布训练后模型，与 SDK 运行时修改记忆是两件事；本轮未核验权重或训练收益。

初筛也排除了名称误导：REA 是逆向工具，Osiris 是情报地图，OpenFlux 是隧道，AgentMesh 是网络基础设施。它们不因名字或使用 agent 就成为本题的自进化框架。仍按正常收录规则处理，不因与本题无关而丢弃。

## 优先级：先补现有链，而非换底座

以下优先级是适配判断，不是性能排名。所有收益均待隔离实验验证。

| 优先级与适配度 | 借鉴对象 | 吸收机制 | 对应现有位置 | 不照搬的部分 |
|---|---|---|---|---|
| 优先，高 | Jiuwen 单 harness RSI | 最终补丁经过筛选后，对最终实际包重新运行；已知成功任务不能退步 | `agent-harness-improvement` 的落地链，连接现有 `scripts/skill_eval/runner.py` | 内部留出集强制为零；队员经验自动写共享库 |
| 优先，高 | Penguin 的离线优化协议 | 冻结候选版本、单轮单假设、保留逐题轨迹与还原点 | 同一改进链的暂存包与验证产物 | 模型填写汇总分；同题最高分即晋升；后台直接改 skill |
| 其次，中 | Headroom learn | 从工具失败和重复循环生成可追溯提案；多宿主日志适配 | 已有会话采集和判卷模块 | 再造一个 writer；直接 apply 全局规则；把省 token 估算当收益 |
| 其次，中 | Atomic 的来源约束 | 姓名等受支持字段不能由旧幻觉自证；区分正文与标签变更。这不是所有笔记的真实性保证 | `assist-mem`、`compact-memory` 的证据和整理规则 | 以“答案采用该记忆”作为正确奖励；自动反思直接写正式账本 |
| 按需，中 | Hy-Memory 的代码变更链 | 将经验绑定精确 diff，保留不可变版本关系 | `assist-learn` 的项目笔记，与既有提交证据联结 | 引入整套图数据库；把同批交叉链接当独立证据 |

FounderOS 的 claim/fact 分离和临时提示 TTL 可作参考，但现有体系已有候选与正式记忆的边界，本轮不优先新增。具体的 `ImprovementTaskQueue.apply()` 只更新 Q 值，不能证明建议已被执行；其他记忆和提示写入路径仍存在。不要因队列状态变成 Applied 就将它算作改善成功。

## 为什么不直接装

### 有评分，不代表有可信验收

Penguin 的测试源码明确接受子运行分数为 80 和 82，而题目级汇总分为 80.2。scoreboard 读取服务展示存储值，不复算成 81。这是源码与测试断言固定的行为；本轮没有执行测试，也没有复现攻击。另开一个评价模型，也不能替代汇总一致性检查。

Jiuwen 有程序判分、全量回归和安装回滚。它比只写反思更完整。但单 harness 构造器把 `candidate_holdout_cases` 覆盖为零，全部任务参与优化。它能检查已见任务回归，不能用同一批题证明未见任务收益；使用者仍可在外部另设封存验收。

证据：[Penguin 测试](https://github.com/Prism-Shadow/penguin-harness/blob/7e08d23f67e8f3945d37fbc793d398d55454b9bd/packages/server/test/benchmarks.test.ts#L302-L334)、[Jiuwen 依赖实现](https://github.com/openJiuwen-ai/agent-core/blob/4e6e53d4f3a97e4f39651be337ba309835de15e0/openjiuwen/rsi/harness_rsi/single_harness/iterative.py#L150-L174)。主会话已重新读取两处。

### 只预览，不代表不外发

Headroom 在默认失败学习模式中，先扫描和分析会话，再把 dry-run 传给 writer。默认预览只阻止写文件，不阻止前面的模型分析。云后端可能收到用户文字、工具参数和失败片段。因此，本次没有运行它扫描你的会话。

现有改进路线已有材料范围、服务商确认与脱敏要求。外部适配器应服从这些要求，不能用一次 `--apply` 绕过它们。证据：[实际调用顺序](https://github.com/headroomlabs-ai/headroom/blob/fbf7bc3278c11975299b9bd0a2ecf200dfd25a05/headroom/cli/learn.py#L289-L359)。主会话已重读该顺序。

### 记忆被使用，不代表记忆正确

Atomic 的投票提示将“答案采用了这条记忆”作为正票理由。Hy-Memory 的 System 2 新建 schema 强证据门默认关闭；启用后才执行该项独立来源要求。这不表示整个项目没有其他证据检查。它们各自有真实治理机制，但都不能直接变成全局规则的效果晋升门。

来源：[Atomic 姓名约束](https://github.com/AtomicBot-ai/atomic-agent/blob/7899d173e0a07665f45cf014de065eb38f405127/src/memory/reflection/reflection-runner.ts#L425-L479)、[Hy 默认开关](https://github.com/Tencent-Hunyuan/Hy-Memory/blob/0c59413ad81158a3bd4748beb7bdda354659b3af/hy_memory/pipelines/system2_agent.py#L72-L94)、[schema 校验函数](https://github.com/Tencent-Hunyuan/Hy-Memory/blob/0c59413ad81158a3bd4748beb7bdda354659b3af/hy_memory/pipelines/system2_agent.py#L813-L837)。

**[推断：依据是奖励定义和证据开关，未做污染实验]** 如果把引用次数、使用次数或模型置信度直接当正确性，错误信息可能越用越稳。应保留反证，并用独立任务结果检验。

## 当前系统最值得补的三个接口

这些是后续研究建议，不是本轮实现承诺，也不是新命令或已存在的数据格式。

### 冻结实际输入

现有改进计划冻结会话清单，但判卷阶段重新取正文。下一步实验包应绑定已批准的脱敏文本、内容哈希、实际参数、提示词版本和模型版本。重判不能静默换输入。

### 连接已有行为评测

已有 runner 读取真实工具调用日志，并支持留出与回归样本。其自带基线臂是禁用技能的对照，不自动等于旧版与新版对照；需要按冻结版本分别运行。先复用它，不另造一套“模型说通过”的验证器。它目前擅长技能路由和受支持的输出判据，不能自动证明所有 hook、记忆或工作流收益。

### 绑定最终候选与晋升证据

人审删掉部分修改后，最终包可能已经不同于被测版本。应对最终实际产物重新验收，并绑定提交、样本和原始日志。正确性、安全回归不能用总分上涨抵消；生效仍走人工批准与受管发布。

## 可交给后续方案的最小实验

**问题。** 某个技能描述或规则修改，是否减少真实误路由，同时不削弱安全边界？这比“让整个系统自动变聪明”更可验收。

**具体输入。** 用本次真实请求作诊断场景：“执行 intake-tabs，并深入研究项目能否提升现有 harness。”应观察到收录与机制研究分工，且不因调研授权而安装框架、扫描私人会话或修改全局配置。本场景已经公开参与讨论，只能作诊断／回归材料，不能再当封存验收题。

**做法。** 冻结旧版与一个候选，限定一个技能表面。另准备不向候选生成者展示的改写请求、近邻误触发和拒绝场景。由现有 runner 留下原始调用日志，再人工检查目标产物。具体样本量、重复次数与费用上限应在实验前批准，不在本报告中任意定默认值。

**验收。** 对比目标完成、误路由、危险动作、重复摩擦、成本和耗时。报告逐题结果和不确定性；如果样本不足，就只报冒烟观察，不报成功率提升。最终版本通过封存验收后，也不自动取得发布权。

**回退。** 候选留在隔离分支；未通过不晋升。已发布修改通过受审查的 Git 改动撤回，不覆盖其他会话新增内容。

## 运行边界与未验证项

- **权限。** 本轮只读公开源码和既有机制实现。没有读取私人会话、记忆正文或凭证，没有执行上游技能或安装器。
- **外发与费用。** 没有启动外部框架的模型分析。后续实验涉及材料外发、执行模型与配额，需按现有流程单独确认范围和费用。
- **写入。** 本轮只写索引及调研交付物，不改现有 harness。调研不等于允许自动安装、自动写规则或自动晋升。

[未验证：尚未执行个人封存任务实验] 不能给出提升比例、净节省费用或可靠的跨框架性能排名。报告也不证明默认文件权限、sandbox 或 rubric 隔离已经安全。

深挖子任务有一次对 Hy-Memory 缓存的 grep 被权限系统拒绝；未绕过。该搜索未完成，不将缺失结果写成事实。其他结论的限定范围见证据报告。
