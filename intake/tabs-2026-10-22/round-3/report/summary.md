### 为什么仍收录三个容易误判的项目

**DeepSeek Report 不是只有成稿。** 完整树有六个 Python 文件、采集 JSON、图表与分页检查实现。它作为研究模式与代码档案有可复用实质；缺路径修复和完整许可文件被显著列出，没有把它包装成开箱即用服务或投资结论认证。

**We-Video 不是纯前端，也不是完整产品。** 主会话独立枚举固定提交：任务 API 只有创建、审批、附件三类 route 文件。页面把补接口列为采用前提，而不是把后端模块存在冒充浏览器流程接通。

**ArtCraft 有实质原创客户端，但不能整包随意分发。** 它的 NOTICE 明确不授权任天堂音效等第三方素材，历史改许可提交还列出来源未清的图片。页面仅按作者桌面代码的授权范围收录；不替除外资产、独立服务或模型供应商做权利清理。

这三项没有达到“内容为空、主体是他人原样拷贝、冒用许可或只有无用途伤害载荷”的提议条件。风险写进反选与存疑，不凭名称或不成熟就排除；旧提议中的具体复制声明或提取授权问题也没有因此自动豁免。

### 最影响实际选择的三组边界

- **同一包名不等于同一产品成本。** KittenTTS 的微型英文模型和新版克隆是两套架构；text-to-cad 则完全依赖你已有的 agent 提供模型。不要按项目名推算显卡、语言与授权。
- **本地界面不等于本地数据。** ArtCraft 的普通生成和截图依赖云端；We-Video 把文本交模型与语音服务；text-to-cad 的遥测与版本检查各有控制。
- **机器检查不等于效果验收。** Ghidra 超时可能留下部分结果；DeepSeek Report 的质控只告警不失败；We-Video 的亮度检查不核事实，CAD 的摘要哈希也不证明尺寸正确。
